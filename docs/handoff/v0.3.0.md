# Handoff — v0.3.0 (MMSC / KJS-FTB-MMSkillComponents)

Feature release on top of [v0.2.1.md](v0.2.1.md). v0.2.0 still holds the big
picture (skill, CLI, workbench architecture, API contract, gotchas); v0.2.1 holds
the DSH panel post-mortem. **This file records the 0.3.0 redesign: multi-pack
library, instant switching with caches, station-grouped recipes, the graphical
recipe builder, the quest-page backdrop and the MMSC branding.**

---

## 1. What the user asked for, and where it landed

| Request | Implementation |
| --- | --- |
| Workbench logo → creeper head, else a sane fallback icon | `renderBrand()` in `ui/public/app.js` injects an inline 16×16 creeper SVG into `#brandLogo`; it needs no asset file and scales to any size. |
| Pack directory → DSH-workspace-like list of packs, switchable in the app | `GET/POST /api/v1/packs` + `$MMSC_HOME/library.json`; header dropdown `#packSwitch`. |
| Cache per pack; switching must not rescan; only search/edit or an explicit “re-detect” refreshes | `packCache` (LRU 4) in `ui/server.mjs`; `POST /api/v1/refresh` is the only rescan path; the header button 「重新检测」 calls it. |
| Sidebar: 总览 / 物品 unchanged, 合成表 → 合成 with a work-station filter | Stations are computed server-side (`STATIONS`, `stationOf()`), exposed as `/state.stations` and `/recipes?station=`, rendered as chips in `#stationBar`. |
| New recipe → graphical builder (3×3 grid, ordered/shapeless, click a slot to search items; furnace-like stations pick input/output/time) | `openRecipeBuilder()` + `slotNode()` + `openPicker()` + `buildSpec()`; furnace family adds `xp` and `cookingTime`. |
| 任务节点 → 任务; the background image moves into the quest page | Background now lives in the 任务 toolbar (`任务背景图` / `移除背景`); the canvas draws it via `--quest-bg` behind the node graph. |
| Workbench renamed MMSC; MC/loader/KubeJS versions move under the logo; old pack pill removed | `#versionLine` under the brand; header `#packSwitch` replaces the pill. |

## 2. Backend (`ui/server.mjs`, ~840 lines)

### 2.1 Pack library

```js
const LIBRARY_DIR = process.env.MMSC_HOME ?? join(homedir(), '.mmsc');
const LIBRARY_FILE = join(LIBRARY_DIR, 'library.json');
// { packs: [{ path, name, addedAt, lastOpenedAt }], active }
```

`loadLibrary()` / `saveLibrary()` write through a temp file + rename, so a crash
cannot truncate the list. `packList()` annotates each row with `exists` (live
`statSync`) and `active`, sorted by `lastOpenedAt`.

### 2.2 Index cache (the reason switching is instant)

```js
const packCache = new Map();      // resolved pack root -> { detection, items, recipes, quests }
const PACK_CACHE_LIMIT = 4;
```

`ensureItems/ensureRecipes/ensureQuests({ force })` return the cached object with
`kind: 'cache'` and only call `buildItemIndex` / `buildRecipeIndex` /
`loadQuestDir` on a miss or with `force`. `pending` de-duplicates concurrent
builds of the same kind. Measured on the test corpus: re-select **33 ms** (all
cached), forced recipe rebuild **189 ms**.

### 2.3 Stations

```js
const STATIONS = [
  { id: 'crafting',    label: '工作台',        match: /crafting/ },
  { id: 'furnace',     label: '熔炉系',        match: /(smelting|blasting|smoking|campfire_cooking|fire_cooking|kiln|oven|cooking)/ },
  { id: 'stonecutter', label: '切石机',        match: /stonecutting|stonecutter|cutting|sawmill|sawing/ },
  { id: 'smithing',    label: '锻造台',        match: /smithing/ },
  { id: 'special',     label: '其他/模组机器', match: () => true },
];
```

`stationOf(type)` returns the first match; `special` is the catch-all for modded
machines. `/api/v1/state.stations` carries the counts, each recipe carries its
`station`, and `/api/v1/recipes?station=` filters.

### 2.4 New endpoints

`/api/v1/packs` (GET, POST add/select/remove/rename), `/api/v1/refresh`
({ scope: all|items|recipes|quests }). `/api/v1/open` is kept as an alias for
`select`. Full contract: [../API.md](../API.md).

### 2.5 Background semantics changed

The image is now explicitly **the quest page backdrop**. Settings keep
`background` (extension) and `backgroundAt` (cache-busting timestamp);
`POST /api/background` accepts the same `{ type, data }` payload as before and
returns `{ ok, url, ext }`. Nothing is uploaded anywhere.

## 3. Frontend

- `ui/public/index.html` — brand block (`#brandLogo` + `MMSC` + `KubeJS + FTB
Quests`), `#versionLine`, five nav entries (总览/物品/合成/任务/设置), header pack
  switch, `#stationBar`, quest background controls, `#picker` overlay.
- `ui/public/app.js` — brand SVG, pack menu, station chips, graphical builder,
  item picker, quest backdrop, pack table in settings, `renderVersionLine()`.
- `ui/public/style.css` — pack menu, station chips, builder/slot/picker styles,
  quest canvas backdrop with a 0.34→0.62 gradient scrim so nodes stay readable.

The graphical builder writes **specs**, not scripts: the same `POST /api/v1/edit`
path regenerates `kubejs/server_scripts/zz_kjsftb_edits.js` through
`gen-js.mjs`, so generation-specific syntax (legacy `onEvent` vs `ServerEvents`)
is still decided by the detected pack, never by the browser.

## 5. Gotchas for the next model

1. **`MMSC_HOME`** — the pack library is machine-global (`~/.mmsc/library.json`).
   Tests and scratch sessions must set `MMSC_HOME` to a temp dir or they will
   inherit a developer's packs.
2. **Cache invalidation is manual by design.** A jar replaced on disk keeps its
   cached index until 「重新检测」 (`POST /api/v1/refresh`). Item/recipe disk caches
   under `<pack>/.kjsftb/` are keyed by jar size+mtime, so a replaced jar does
   invalidate those on the next rebuild.
3. **The station regex order matters.** `furnace` matches `cooking`, so modded
   cooking machines classify as 熔炉系; anything unmatched falls to `special`.
4. **The builder never emits raw JS.** Keep it that way: all writes go through
   `buildSpec()` → `/api/edit` → `gen-js.mjs`, which is version-aware.
5. **Background belongs to the quest view.** Do not move it back into settings;
   the API doc and the handoff both describe it as the quest backdrop.
6. `ui/public/*` has no build step and no framework: keep it that way unless the
   frontend is being replaced behind the documented API.
