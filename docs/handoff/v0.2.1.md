# Handoff — v0.2.1 (MMSC / KJS-FTB-MMSkillComponents)

Short delta on top of [v0.2.0.md](v0.2.0.md), which still holds the architecture,
the API contract and the gotchas. Read that one for the whole picture; this file
records what changed in 0.2.1 and what a successor must re-verify.

Version 0.2.1 is a bug-fix release: the DSH settings panel went from "renders but
cannot talk to its host" to "should work after a restart", and the test harness
that let the bug through was tightened.

---

## 1. Symptom

DSH → Settings → 魔改工作台 rendered the title and, immediately below it, one line:

```
无法读取工作台状态：HTTP 400 · (empty body)
```

Every `/api/mmsc/*` call failed the same way, including a route that should have
answered without touching the config store or the child process.

## 2. Root cause

`dsh-plugin/mmsc-workbench/index.js` registered its routes like this:

```js
ctx.effect(
  () => ctx.inject(['connection'], (scope) => {
    scope.effect(() => scope.connection.fetch.register(route), 'label');
  }),
  'mmsc-workbench: routes',
);
```

A Cordis effect factory must **return a disposer**. `ctx.inject(...)` returns
`undefined`, so the effect threw during `apply()` and the whole host row aborted
before a single route existed. The renderer was unaffected, which is why the page
still drew — it just had nothing to call.

The working reference is `dsh-model-visibility/index.js`: it calls
`ctx.inject(['settings'], cb)` and `ctx.inject(['llm','connection'], cb)` directly
at `apply()` level, and only wraps the individual route registrations in
`scope.effect(() => connection.fetch.register(...), 'label')`.

Fixed shape (index.js):

```js
ctx.inject(['connection'], (scope) => {
  const register = (route) =>
    scope.effect(() => scope.connection.fetch.register(route), `mmsc-workbench: ${route.path}`);
  // … routes …
});

// unchanged, and correct: the two-argument effect form used by the reference plugin
ctx.effect(() => () => void supervisor.stop(), 'mmsc-workbench: shutdown');
```

## 3. Why the tests did not catch it

`tests/workbench-plugin.test.mjs` used a fake context whose `effect()` accepted
anything:

```js
effect(factory) {
  const dispose = factory();
  if (typeof dispose === 'function') disposers.push(dispose);  // silently tolerated undefined
  return dispose;
}
```

It now mirrors Cordis and throws:

```js
effect(factory) {
  const dispose = factory();
  if (typeof dispose !== 'function') throw new TypeError('effect factory must return a disposer');
  disposers.push(dispose);
  return dispose;
}
```

A new test asserts that `apply()` registers all seven routes
(`ping`, `status`, `config`, `start`, `stop`, `restart`, `open`), so an aborted
row fails loudly. Baseline is now **57/57** (`node --test` from the repo root).

## 4. Diagnostics added

- Host: `GET /api/mmsc/ping` → `{ ok: true, entry, pid, api }`. It reads nothing
  and spawns nothing, so it separates "route not mounted" from "handler threw".
- Client: the first refresh pings before fetching status. Success shows
  「主机路由已连通（… · pid …）」; failure shows the HTTP status, the response text
  (truncated to 300 chars) and the hint that the host row only mounts at DSH
  startup, so the app must be restarted.

## 5. Verify after restarting DSH

1. Quit the desktop app completely and start it again (a renderer reload is not
   enough — bundle host rows mount during startup).
2. Settings (`Ctrl+,`) → 魔改工作台.
3. Expected, top to bottom: 「主机路由已连通（/api/mmsc/ping · pid …）」; a status
   pill reading `stopped`; the port field showing `5599`; the pack directory field
   (may be empty).
4. Click 启动 — the URL line fills in (`http://127.0.0.1:<port>`), 在浏览器打开
   opens the workbench. 重启 keeps the port and swaps the pid. 停止 releases it.
5. If it still answers 400: ping failing means the row is still not mounted —
   check `cordis_inspect_query(host, Config, listConfigs, {name:'@tzyc/mmsc-workbench'})`
   for the `include:mmsc-workbench` entry and confirm
   `dsh.profile.bundles` in the profile `package.json` lists the plugin. Ping
   succeeding while status fails means the handler itself threw; the client now
   shows the body text.

## 6. Files touched

- `dsh-plugin/mmsc-workbench/index.js` — direct `ctx.inject`, ping route.
- `dsh-plugin/mmsc-workbench/client.js` — verbose errors, ping probe, restart hint
  (zh + en dictionaries).
- `dsh-plugin/mmsc-workbench/package.json`, `package.json`, `ui/api-contract.mjs`
  — version 0.2.1.
- `tests/workbench-plugin.test.mjs` — strict effect stand-in + route inventory test.
- `docs/handoff/v0.2.0.md` — 400 entry rewritten as root cause; test count 57.
- `README.md` — handoff link now points at this directory's index.

## 7. Still open

- `git push` is blocked on credentials: the machine has no stored GitHub
  credential and `GIT_TERMINAL_PROMPT=0` is set. Local commits are complete; the
  remote `origin` is configured. A successor with a token or SSH key can push.
- GUI verification of the panel (section 5) has to be done by a human on the
  desktop session; it cannot be automated from inside the app that hosts it.
- Unrelated cosmetic debt noted earlier: recipes whose output is produced by mod
  logic are labelled as such instead of showing a fake result, and the detector
  labels a version-less `kubejs.jar` as `generation assumed (newest)` rather than
  guessing a number.
