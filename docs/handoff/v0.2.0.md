# Handoff — v0.2.0 (MMSC / KJS-FTB-MMSkillComponents)

Audience: the next model or person picking this repository up. Read this first;
it records what works, what is deliberately shaped the way it is, and what is
still open. Everything below was verified on Windows 11 with Node 24 in the
workspace `D:\code\KJS-FTB-MMSkillComponents`.

---

## 1. What this repository is

One repository, four cooperating deliverables that all share the same version
knowledge:

| Piece | Path | What it does |
| --- | --- | --- |
| DSH skill | `SKILL.md` + `references/` | Tells an AI agent how to write/repair KubeJS scripts and FTB Quests data for a specific Minecraft version. |
| CLI | `bin/kjsftb.mjs` + `scripts/*.mjs` | `detect`, `lint`, `ftbq`, `snbt`, `recipe new`, `quest new`, `quest chapter`, `quest id`, `ui`. |
| Workbench | `ui/server.mjs` + `ui/public/` | Zero-dependency local web UI: open a pack folder, browse items with icons, edit recipes, view FTB Quests graph, set a background. |
| DSH settings panel | `dsh-plugin/mmsc-workbench/` | A DSH-only settings row that starts/stops/restarts the workbench child process and stores its port/pack directory. |

The skill is symlinked (Windows junction) into
`C:\Users\wangc\.dsh\skills\kubejs-ftbq`, so editing the workspace updates the
installed skill immediately.

### Names

- Full: `KubeJS-and-FTB-Quests-Minecraft-Modded-Skill-Components`
- Common: `KJS-FTB-MMSkillComponents`
- Short: `MMSC`

The npm package name is `kjs-ftb-mmskillcomponents`; the DSH plugin package is
`@tzyc/mmsc-workbench`.

## 3. Version model (the core invariant)

Nothing in this repo is version-agnostic. `scripts/versions.mjs` owns four
generations, and every other module asks it instead of guessing:

| Generation | KubeJS builds | Minecraft | Script style |
| --- | --- | --- | --- |
| `legacy` | 1605.x, 1802.x | 1.16.5, 1.18.2 | `onEvent('recipes', event => …)` |
| `kjs6` | 1902.x, 2001.x, 2004.x | 1.19.2, 1.20.1, 1.20.4 | `ServerEvents.recipes(event => …)`; `onEvent` exists only as a throwing stub |
| `kjs7` | 2100.x, 2101.x | 1.21, 1.21.1 | `ServerEvents.recipes(...)`; `onEvent` is gone |
| `kjs8` | 8.x (e.g. `26.1.2-8.0.8`) | 26.1.2 | same as kjs7 with renames (`ResourceLocation`→`Identifier`, `ItemToolTiers`→`ItemToolMaterials`) |

Detection order: `modrinth.index.json` → CurseForge `manifest.json` →
`minecraftinstance.json` → Prism `mmc-pack.json` → KubeJS jar name → quest
directory shape. `detectPack()` returns `generation`, `generationSource`, and
`generationAssumed` so the UI can say “kjs7 (assumed)”.

FTB Quests is versioned separately (`FTBQ_VERSIONS`: 1.16, 1.18, 1.19, 1.20.1,
1.21.1). Two facts that bite everyone:

1. FTBQ chapter files are **SNBT**, not JSON, since 1.16.
2. `data.snbt`'s `version:` is `13` in every release — it cannot identify a
   version. Use the jar name or field presence.

## 4. Workbench architecture

### Server

`ui/server.mjs` exports `startWorkbench({ root, port, host })` and binds
`127.0.0.1` only. It owns no framework: a `http.createServer` handler, JSON
helpers, and a small static-file server for `ui/dist` (if a replacement
frontend is ever built) falling back to `ui/public`.

State lives in memory (`state`) and is rebuilt by `openPack(root)`:
detection → item index → recipe index → quest graph. The expensive indexes are
cached on disk under `<pack>/.kjsftb/`:

| File | Produced by | Invalidated by |
| --- | --- | --- |
| `items-cache.json` | `items.buildItemIndex` | jar size/mtime, registry-dump mtime, client-jar path change |
| `recipes-cache.json` | `recipes.buildRecipeIndex` | same key plus script file list |
| `edits.json` | the UI edit log | user edits |
| `settings.json` | settings endpoint | user settings |
| `background.<ext>` | background upload | user remove |

### Data sources, in priority order

Items: `/kubejs export` dump (`kubejs/exported/registries/item.json` and
`block.json`) > jar item models > jar item definitions > blockstates.
Recipes: jar `data/<ns>/recipes|recipe/**` > pack `datapacks/*/data` >
`kubejs/data` > `kubejs/{server,client,startup}_scripts/**.js` (later wins).

Icons: direct `assets/<ns>/textures/item/<path>.png`, then the block texture,
then the item model's `parent` chain (depth 3) resolved to a texture. With the
three test jars this covers ~90% of items; `minecraft:` items have no icons
unless the user points “client jar” at their game jar.

### The edit flow (important)

The workbench never rewrites recipes in jars. Every UI edit appends to
`.kjsftb/edits.json` and regenerates **one** file:

```
kubejs/server_scripts/zz_kjsftb_edits.js
```

using `gen-js.mjs` with the detected generation. Removing every edit deletes
that file. `/api/lint` runs the normal linter over the pack so generated code
is checked by the same rules as hand-written code.

### API contract

`ui/api-contract.mjs` is the single source of truth: `API_VERSION='v1'`,
`SERVER_VERSION='0.2.0'`, the endpoint table, and `canonicalPath()` which maps
`/api/v1/x` → `/api/x` so both forms work. `docs/API.md` documents every
endpoint with JSON samples. A replacement frontend only needs:

- `window.MMSC_API_BASE` (default `''`) and `window.MMSC_API_VERSION`
  (default `'v1'`),
- `GET /api/version` to discover the surface,
- the four guarantees listed at the end of `docs/API.md`.

CORS is enabled for `/api/*` (echoed `Origin`, `Vary: Origin`, `OPTIONS` → 204),
so a separately hosted frontend can call the server directly.

## 5. DSH settings panel (`dsh-plugin/mmsc-workbench`)

This piece exists because starting a local child process is impossible from a
browser page. It is **DSH-only** by construction:

- `package.json` declares `dsh.bundle.patch` and
  `dsh.client = { platform: 'web', immediately: true }`.
- `client.js` starts with a guard: if `window.__ModuleLoader__` is missing it
  returns without doing anything, so loading the file outside DSH is inert.
- `index.js` registers routes through
  `ctx.inject(['connection'], scope => scope.connection.fetch.register(...))`
  (same mechanism as `dsh-model-visibility`) and supervises the child with
  `spawn(process.execPath, [bin, 'ui', …], { env: { ELECTRON_RUN_AS_NODE: '1' } })`
  — Electron’s Node build is reused, so no system Node is required.

Routes (all authenticated same-origin): `GET /api/mmsc/status`,
`GET /api/mmsc/ping` (diagnostic), and `POST /api/mmsc/{config,start,stop,restart,open}`.
Config persists at `$DSH_HOME/mmsc-workbench.json` with atomic writes and
sanitising (ports outside 1–65535 fall back to 5599).

Install:

```
plugin_manager action=install_bundle target=<repo>\dsh-plugin\mmsc-workbench
```

The profile then contains
`"@tzyc/mmsc-workbench": "link:D:/code/KJS-FTB-MMSkillComponents/dsh-plugin/mmsc-workbench"`
plus the bundle id in `dsh.profile.bundles`. The plugin row appears in
`cordis_inspect_query(host, Config, listConfigs)` as
`{id: 'include:mmsc-workbench', patchId: 'mmsc-workbench'}`.

**Root cause found (v0.2.1):** the settings page rendered correctly, but every
`/api/mmsc/*` call returned an empty **HTTP 400** because the host half never
finished loading. `apply()` wrapped the service injection in
`ctx.effect(() => ctx.inject(['connection'], …))`; a Cordis effect factory must
return a disposer, so the row aborted before registering a single route.
`dsh-model-visibility` calls `ctx.inject([...], cb)` directly, and the plugin now
does the same. Two follow-ups shipped with the fix:

- the fake context in `tests/workbench-plugin.test.mjs` now throws when an
  effect factory does not return a disposer (this exact mistake used to pass);
- a `GET /api/mmsc/ping` route plus verbose client errors distinguish “host row
  not mounted” from “handler threw”, and the panel appends
  “restart DSH and reopen this page” when ping itself fails.

Note that DSH mounts bundle host rows at startup: after installing or changing a
bundle, restart the desktop app (the renderer-only reload, `Ctrl+R`, is not
enough).

Do not “fix” this by spawning a raw `http.Server` in the host: routes must go
through `connection.fetch` to keep DSH’s same-origin authentication.

## 7. Gotchas worth inheriting

- **Never** round-trip UTF-8 source files through PowerShell
  `Get-Content`/`Set-Content`: it mangles `—`, `…`, and Chinese text. Use the
  file tools, or `[System.IO.File]::ReadAllText/WriteAllText` with
  `UTF8Encoding($false)`. Console mojibake (`鈥?`) is a display artefact, not
  corruption — verify with a strict UTF-8 decode before rewriting.
- **Never** print the whole DSH profile `cordis.yml`/`cordis.patch.yml`: those
  files embed thousands of model entries. Grep them.
- Editing `scripts/*.mjs` requires restarting the workbench process; changing
  `ui/public/*` requires a hard refresh; changing `dsh-plugin/*` requires a DSH
  restart for the host half.
- `node --test tests/` fails on this Node version — run `node --test` from the
  root.
- Recipe caches key on file mtimes: after hand-editing a script, delete
  `<pack>/.kjsftb/recipes-cache.json` (or use `--force`) or the UI will show
  stale recipes.
