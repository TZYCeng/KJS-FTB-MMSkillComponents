# FTB Quests data format

A pack's progression is a directory of SNBT files, from 1.16 through 1.21.1. It is **not** JSON, and has not been JSON since 1.12 (the 1.12 era used `chapters/*.json`; if you find JSON in a modern pack it is a leftover or a hand-made import, and the mod ignores it).

## 1. Directory layout

```
config/ftbquests/quests/
  data.snbt                 pack-wide settings (one compound)
  chapter_groups.snbt       { chapter_groups: [ { id: "...", ... } ] }
  chapters/<filename>.snbt  one chapter per file, quests inline
  reward_tables/<name>.snbt reward tables (all versions since 1.16)
  lang/<locale>.snbt        translations - 1.21+ only
```

- The file name must equal the chapter's `filename` field. A mismatch creates a duplicate chapter on the next save (`chapter-filename`).
- `data.snbt` and `chapter_groups.snbt` are regenerated with defaults if missing; chapters and reward tables are loaded from their folders.
- Chapter `group` is the **string id** of a chapter group from `chapter_groups.snbt`, or `""` for the default group.

## 2. `data.snbt` (pack settings)

Real 1.21.1 example, one entry per line, tab-indented:

```snbt
{
	default_autoclaim_rewards: "disabled"
	default_consume_items: false
	default_quest_shape: "circle"
	default_reward_team: false
	detection_delay: 60
	disable_gui: false
	drop_loot_crates: false
	emergency_items_cooldown: 300
	grid_scale: 0.5d
	icon: { id: "minecraft:book" }
	lock_message: ""
	loot_crate_no_drop: { boss: 0, monster: 600, passive: 4000 }
	pause_game: false
	progression_mode: "flexible"
	show_lock_icons: true
	version: 13
}
```

- **`version: 13` is constant across 1.16 – 1.21.1.** Do not use it to identify the pack version.
- `icon` is a compound `{ id: "...", ... }` in 1.21+; in 1.16 – 1.20.1 it is a plain string (`icon: "allthetweaks:atm_star"`).
- `title` exists in 1.16 – 1.20.1 and moved to the lang table in 1.21.
- `show_lock_icons`, `verify_on_load`, `presets`, `fallback_locale`, `suppress_all_autoclaiming` only exist in 1.21.1+ (`field-too-new` when used earlier).

## 3. Chapter file

```snbt
{
	default_hide_dependency_lines: false
	default_quest_shape: ""
	filename: "welcome"
	group: ""
	icon: { id: "ftbquests:book" }
	id: "5B00676D79306EA2"
	images: [ ... ]
	order_index: 0
	progression_mode: "flexible"
	quest_links: [ ... ]
	quests: [ ... ]
}
```

| key | type | notes |
|---|---|---|
| `filename` | string | must match the file name; `^\w+$` |
| `group` | string | chapter group id, `""` = default |
| `id` | 16 hex | unique |
| `order_index` | int | position in the chapter list |
| `icon` | compound | `{ id: "mod:item" }` or a custom icon |
| `images` | list | `{ image, x, y, width, height, rotation, corner, click, hover }` (doubles) |
| `quest_links` | list | `{ id, linked_quest, x, y }`, both ids 16 hex |
| `quests` | list | quest compounds (see §4) |
| `default_quest_shape`, `default_quest_size`, `default_hide_dependency_lines`, `default_min_width`, `default_repeatable_quest`, `require_sequential_tasks`, `progression_mode`, `always_invisible`, `autofocus_id`, `hide_quest_*`, `hide_text_until_complete`, `preset` | mixed | chapter-level defaults; `hide_quest_details_until_startable` / `hide_quest_until_deps_*` / `preset` are 1.21.1+ |

## 4. Quest compound

```snbt
{
	dependencies: ["3BC0A50886A3222B"]
	icon: { id: "minecraft:chest" }
	id: "A1B2C3D4E5F60718"
	rewards: [ { id: "...", type: "xp", xp: 10 } ]
	shape: "circle"
	size: 1.0d
	tasks: [ { id: "...", type: "item", item: "minecraft:chest", count: 1 } ]
	x: 0.0d
	y: 1.5d
}
```

| key | since | meaning |
|---|---|---|
| `x`, `y` | all | doubles, grid coordinates; `0.0d` style |
| `dependencies` | all | list of quest ids; `min_required_dependencies` allows "any N of them" |
| `tasks`, `rewards` | 1.18+ (1.16 keeps them in the same compound too) | lists |
| `shape`, `size` | all | `circle`, `square`, `diamond`, `pentagon`, `hexagon`, `octagon`, `heart`, ... |
| `icon`, `icon_scale` | all / 1.20.1+ | icon compound; `icon_scale` double |
| `invisible`, `invisible_until_tasks` | 1.18+ | |
| `optional` | all | quest does not gate dependents |
| `min_width`, `hide_dependent_lines`, `hide_lock_icon`, `max_completable_dependents`, `repeat_cooldown`, `progression_mode`, `can_repeat`, `ignore_reward_blocking`, `dep_control_pts`, `preset`, `guide_page` | version-dependent | see `references/ftbquests-types.md` for the "since" table |
| `title`, `subtitle`, `description` | 1.16 – 1.20.1 only | **in 1.21+ they live in `lang/`** |

Ids: 16 uppercase hex digits generated by FTB (the in-game editor or `/ftbquests change_progress` never reuse them). `getCodeString` treats them as unsigned 64-bit hex, so lowercase parses too, but write uppercase to match FTB's own output.

## 5. Tasks and rewards

Every task and reward is a compound with `id`, `type`, and type-specific fields. The full type list, availability per version and required/optional fields are generated into `references/ftbquests-types.md`.

- Type ids are written **bare** in SNBT (`type: "item"`), though the registry key is `ftbquests:item`.
- An **unknown** type becomes a Custom task/reward titled `Unknown type: X` — it never completes and is re-saved as `type: "custom"`.
- A **missing** type defaults to `item`; an item task with an empty `item` slot completes on the first item pickup.
- `forge_energy` is registered only by Forge/NeoForge builds; `tech_reborn_energy` only by Fabric.

## 6. Reward tables (`reward_tables/<name>.snbt`)

```snbt
{
	id: "1AB84F34E0981194"
	rewards: [ { id: "...", type: "item", item: { id: "minecraft:diamond", count: 1 } } ]
}
```

Optional `loot_crate` (a `{ ... }` item compound) and `loot_table_id` (long). Table-backed rewards (`random`, `choice`, `all_table`, `loot`) reference a table by `table_id`; a dangling `table_id` is reported as `reward-table-dangling` and the reward claims nothing.

## 7. Translations (`lang/<locale>.snbt`) — 1.21+

```
config/ftbquests/quests/lang/en_us.snbt
config/ftbquests/quests/lang/zh_cn.snbt
```

- One flat compound per locale; the file base name **is** the locale (`^\w+$`, lowercase). Default fallback locale is `en_us`.
- Key shape: `<object type>.<16 hex id>.<field>`:
  - `quest.<id>.title` (string)
  - `quest.<id>.quest_subtitle` (string)
  - `quest.<id>.quest_desc` (**list of strings**, one entry per line)
  - `chapter.<id>.title` (string)
  - `chapter.<id>.chapter_subtitle` (**list of strings**)
- Empty strings / empty lists are not written back.
- A key whose id does not exist is dropped on the next save (`lang-orphan`); a key that is not three dot-separated parts is ignored (`lang-key-shape`); `quest_desc` must be a list, not a string (`lang-value-shape`).
- Missing translations fall back to the English table; the in-game editor highlights them only when FTB Quests client config `HILITE_MISSING` is on.

## 8. SNBT syntax rules FTB relies on

- One entry per line, **tab** indentation, no commas between entries.
- Strings are double-quoted; optional escapes `\" \\ \n \t \r \uXXXX`.
- Numeric suffixes are meaningful: `b` byte, `s` short, `L` long, `f` float, `d` double. Coordinates and sizes are doubles: `0.5d`, `3.0d`. Writing `3` where a double is read usually still works (numeric tags convert), but FTB's own writer emits `3.0d` and round-tripping through a formatter should keep it.
- Lists of compounds use `[` on its own line; short scalar lists are written inline: `dependencies: ["AAAA...", "BBBB..."]`.
- Typed arrays `[B; 1, 2]`, `[I; ...]`, `[L; ...]` appear in NBT-carrying fields.

`snbt check <file|dir>` parses and reports line/column errors; `snbt format <file> --write` rewrites in FTB's layout (tab indent, no commas, `d` suffix for the known coordinate keys).

## 9. Editing rules

1. **Back up** `config/ftbquests/quests/` before bulk edits; diff afterwards (`git diff --stat`).
2. **Never invent or copy ids.** Get a fresh one from `kjsftb quest id` (or the editor). Duplicated ids make one object overwrite the other on load.
3. **Never point a dependency / quest_link / table_id at a chapter id.** Ids share one namespace, but the object kinds differ and the validator reports `dependency-dangling`.
4. Prefer the generators (`kjsftb quest new` / `quest chapter`) for new content: they pick ids, write the text to the right place for the detected version, and keep FTB's formatting.
5. After a manual edit, run `kjsftb ftbq <pack>` and fix every error. Warnings are usually real too (silent drops, orphan lang keys, fields newer than the pack).

## 10. Validator codes (1.21.1 wording)

| code | severity | meaning |
|---|---|---|
| `snbt-parse` | error | file does not parse (line/column reported) |
| `quest-dir-missing` | error | no `quests` directory found |
| `data-missing` | error | `data.snbt` absent (FTB regenerates defaults) |
| `chapter-filename` | warning | `filename` differs from the file name |
| `chapter-group-dangling` | error | `group` id not in `chapter_groups.snbt` |
| `id-missing` / `id-invalid` | error | quest/task/reward without a usable 16-hex id |
| `duplicate-id` | error | same id used twice |
| `dependency-dangling` / `dependency-self` | error | dependency target missing / self-reference |
| `quest-no-tasks` | warning | quest has no tasks (editor-only completion) |
| `task-type-missing` / `task-type-unknown` | error | see §5 |
| `task-field-missing` / `*-field-unknown` | error / warning | required field absent / unrecognised key |
| `field-too-new` | warning | field introduced after the target version |
| `rewards-unreachable` | info | rewards on a task-less quest |
| `reward-table-dangling` / `reward-table-empty` | error / warning | table reference problems |
| `quest-link-dangling` | error | `linked_quest` missing |
| `quest-overlap` | warning | two quests on the same coordinates |
| `lang-key-shape` / `lang-type-unknown` / `lang-orphan` / `lang-value-shape` | warning | translation table problems |
| `lang-missing` | warning | 1.21+ quests without a title entry (summary + first ids) |
