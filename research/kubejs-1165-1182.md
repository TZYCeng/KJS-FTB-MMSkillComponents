## 1. Script folders, packs and load order

### 1.1 Folder constants

`KubeJSPaths` (`1605 common/.../kubejs/KubeJSPaths.java:14-23`, `1802 common/.../mods/kubejs/KubeJSPaths.java:14-23`) defines `DIRECTORY` = `<game folder>/kubejs` (`Platform.getGameFolder().resolve("kubejs")`, :14), `DATA` = `data` :16, `ASSETS` = `assets` :17, `STARTUP_SCRIPTS` = `startup_scripts` :18, `SERVER_SCRIPTS` = `server_scripts` :19, `CLIENT_SCRIPTS` = `client_scripts` :20, `CONFIG` = `config` :21, `EXPORTED` = `exported` :22, `README` = `README.txt` :23. `get(PackType)` maps `CLIENT_RESOURCES`→`ASSETS` and everything else→`DATA` (:38-40 in both). Only `DIRECTORY`, `CONFIG` and `EXPORTED` are created in the static init; the script folders are created lazily by `ScriptManager.loadFromDirectory()`. Exactly three script types exist — there is no `data_scripts` folder (`1605 .../script/ScriptType.java:21-24`, `1802 .../script/ScriptType.java:22-25`).

### 1.2 The three types and their reload triggers

| Type | Folder | Loaded when | Log |
| --- | --- | --- | --- |
| `startup` | `kubejs/startup_scripts` | once, from the `KubeJS` constructor during mod construction (`1605 .../kubejs/KubeJS.java:105-112`, `1802 :104-111`) | `logs/kubejs/startup.txt` |
| `server` | `kubejs/server_scripts` | every server datapack (re)load: world join, `/reload` (`ServerScriptManager.reloadScriptManager`) | `logs/kubejs/server.txt` |
| `client` | `kubejs/client_scripts` | client resource reload, `F3+T` (`1802 .../client/KubeJSClient.java:64-69`) | `logs/kubejs/client.txt` |

Log path is `logs/kubejs/<name>.txt` (`1605 .../script/ScriptType.java:52-69`, `1802 :63-80`); 1.16.5 logs via log4j `LogManager`, 1.18.2 via slf4j `LoggerFactory`. After evaluating each pack, `ScriptManager.load()` posts `LOADED` and logs `Loaded <i>/<t> KubeJS <type> scripts in <n> s` (`1605 .../script/ScriptManager.java:100-159`, `1802 :98-162`). A startup syntax error aborts mod loading: `RuntimeException("There were startup script syntax errors! See logs/kubejs/startup.txt for more info")` (`1605 :154-156`, `1802 :160-162`).

### 1.3 Discovery: recursive, `.js` only, depth 10

```java
// 1802 common/.../kubejs/KubeJS.java:135-149 (1605 :139-153) — Files.walk(dir, 10).filter(Files::isRegularFile)
// then: name must end with ".js"
```

Subfolders load recursively with `/` normalisation; only `*.js` becomes a script. Pack identity is the **folder name**, so the default namespace is literally `startup_scripts` / `server_scripts` / `client_scripts` (`1802 .../script/ScriptManager.java:70`, `1605 :72`). Script id and log location come from the path: `id = new ResourceLocation(pack.namespace, FILE_FIXER.matcher(pack.pathStart + file).replaceAll("_").toLowerCase())` and `location = UtilsJS.getID(pack.namespace + ":" + pack.pathStart + file)` (`1802 .../script/ScriptFileInfo.java:32-33`) with `FILE_FIXER = Pattern.compile("[^\\w.\\/]")` (`:18`), so `foo bar.js` becomes id `foo_bar.js`.

### 1.4 Load order and header directives

`ScriptFile.compareTo` sorts by priority **descending** (`1802 .../script/ScriptFile.java:43-46`), applied by `pack.scripts.sort(null)` (`1802 .../script/ScriptManager.java:90`, `1605 :92`). `List.sort` is stable, so equal priorities keep `Files.walk` order — filesystem order, **not alphabetical**. Only the **leading** `//` lines are parsed:

```java
// 1802 .../script/ScriptFileInfo.java:49-65

  if (line.startsWith("//")) { var s = line.substring(2).split(":", 2);
```

| Directive | Effect | Cite |
| --- | --- | --- |
| `// priority: 10` | higher runs first; default `0` | `1802 :63` |
| `// ignored: true` | skip the file | `1802 :64` |
| `// ignore: true` | same, **1.18.2 only** | `1802 :64` |
| `// packmode: x` | loads only when equal to `CommonProperties.get().packMode` | `1802 :65`, filter `1802 .../script/ScriptManager.java:78-81` |

Skips are logged, never thrown: `"Failed to pre-load script file " + location + ": " + error` (`1802 .../script/ScriptManager.java:86`).

### 1.5 Datapack scripts

Every `.js` under `<datapack>/data/<ns>/kubejs/` loads as a **server** script in pack `<ns>`: `resourceManager.listResources("kubejs", s -> s.endsWith(".js"))`, grouped per namespace into `new ScriptPackInfo(namespace, "kubejs/")`, sub-path `getPath().substring(7)` (`1802 .../server/ServerScriptManager.java:67-75`, `1605 :55-92`). This is the only way to ship KubeJS code inside a datapack. A typical modpack tree is `kubejs/startup_scripts/{items,blocks,fluids,worldgen}.js`, `kubejs/server_scripts/{recipes,tags,loot}.js`, `kubejs/client_scripts/{tooltips,hud}.js`, plus `config/` and `exported/`.

## 2. Event binding: `onEvent('<id>', fn)`

### 2.1 The function

```java
// 1802 common/.../kubejs/BuiltinKubeJSPlugin.java:356-362
private static Object onEvent(BindingsEvent event, Object[] args) {
    for (var o : ListJS.orSelf(args[0])) {
        event.type.manager.get().events.listen(String.valueOf(o), (IEventHandler) args[1]);
    }
    return null;
}
```

Bound as `event.addFunction("onEvent", ..., null, IEventHandler.class)` (`1802 .../BuiltinKubeJSPlugin.java:293`, `1605 :243`). Consequences: an **array of ids** is accepted, ids are plain strings (dots literal), and the handler is registered on the manager of the script type that is currently loading. `listen()` rewrites `yeet` → `remove` (`1802 .../event/EventsJS.java:33`), so `onEvent('item.yeet', ...)` listens to `item.remove`. 1.18.2 also binds a global `postEvent(id, data?, cancellable?)` (`1802 :294`); 1.16.5 instead exposes an `events` object (`1605 :241`, `ScriptEventsWrapper`).

### 2.2 Which script type receives what — the rule

```java
// 1802 common/.../kubejs/event/EventJS.java:26-35 (identical at 1605 :26-35)
public final boolean post(ScriptType t, String id) {
    if (t != ScriptType.STARTUP && post(ScriptType.STARTUP, id) && canCancel()) { return true; }
    var e = t.manager.get().events;
    var b = e.postToHandlers(id, e.handlers(id), this);
    afterPosted(b); return b;
}
```

1. Server and client events are delivered to **startup handlers first**, then to their own type — a `startup_scripts` file may listen to `recipes`, `player.logged_in`, `level.tick` (1.18.2) / `world.tick` (1.16.5), ...
2. Startup events reach startup handlers **only**: `onEvent('init', ...)` in `server_scripts` registers silently and never runs.
3. `client_scripts` never sees server events; `server_scripts` never sees client events.
4. If a cancellable event is cancelled by a startup handler, the post returns `true` before the owning type is reached.

Dispatch loop (`1802 .../event/EventsJS.java:49-72`): empty handler list → `false`; each `handler.onEvent(event)`; `RhinoException` → `"Error occurred while handling event '" + id + "': " + msg"`; other `Throwable` → `printStackTrace()`. A JS error is logged and swallowed, the remaining handlers still run. `post(ScriptType t, String id, String sub)` (`:37-52`) tries `id + '.' + sub` then `id`, on startup first, then on `t` — used by networking events.

### 3.1 `event.recipes` dispatch table

## 4. Item / block / fluid registry events

### 4.1 How the events are produced

**1.16.5** posts three fixed ids from `initStartup`:

```java
// 1605 common/.../kubejs/BuiltinKubeJSPlugin.java:151-158
new ItemToolTierEventJS().post(KubeJSEvents.ITEM_REGISTRY_TOOL_TIERS);
new ItemArmorTierEventJS().post(KubeJSEvents.ITEM_REGISTRY_ARMOR_TIERS);
new BlockRegistryEventJS().post(KubeJSEvents.BLOCK_REGISTRY);   // "block.registry"
new ItemRegistryEventJS().post(KubeJSEvents.ITEM_REGISTRY);     // "item.registry"
new FluidRegistryEventJS().post(KubeJSEvents.FLUID_REGISTRY);   // "fluid.registry"
```

## 7. Breaking differences between the two versions

### 7.1 From 1.16.5 to 1.18.2

1. Package rename `dev.latvian.kubejs` → `dev.latvian.mods.kubejs`; Architectury moved from `me.shedaniel.architectury` (`1605 .../recipe/RecipeTypeRegistryEventJS.java:8`) to `dev.architectury` (`1802 :3`) — affects `java('...')` and plugins, not plain scripts.
2. `event.create(id, type)` replaces `builder.type(...)`; `BuilderBase.type(String)` now throws (`1802 .../BuilderBase.java:47`).
3. Tool stats moved to `HandheldItemBuilder`: `tool(...)`, `miningSpeed(...)`, `attackDamage(...)`, `attackSpeed(...)`, `tier(String)` are gone from `ItemBuilder` (compare `1605 .../item/ItemBuilder.java:163-180` with `1802 .../item/custom/HandheldItemBuilder.java:25-53`).
4. Id renames: `world.*`→`level.*` (`1802 KubeJSEvents.java:37-41`), `entity.attack`→`entity.hurt` (`:58`); `client.paint_world` removed.
5. Removed ids: `block.drops`, `entity_type.tags`; removed *constants* for `block.registry`/`item.registry`/`fluid.registry`/`block.tags`/`item.tags`/`fluid.tags` — the ids still fire, generated (§4.1, §5.1).
6. Globals dropped: `JsonUtils`, `ToolType`/`TOOL_TYPE_*`, and lowercase aliases `utils`, `text`, `uuid`, `item`, `ingredient`, `block`, `fluid`, `client`; `events` object replaced by `postEvent(...)`. Added: `Component`, `BlockStatePredicate`, `BlockProperties`.
7. Loot `rolls` changed `RandomIntGenerator` → `NumberProvider`; `LootBuilder.pool(...)` removed.
8. Worldgen properties redesigned (§5.3) — old field assignments become silent no-ops.
9. `// ignore: true` is accepted (1.16.5 only honours `// ignored: true`).
10. 1.18.2 adds `client.generate_assets` (`1802 .../client/KubeJSClientResourcePack.java:43`) and `item.model_properties`, documents that startup reload "may not work" (`1802 .../kubejs/KubeJS.java:68-85`), and drops the legacy `kubejs/startup` migration that 1.16.5 performs (`1605 :108-112`).

### 7.2 From 1.18.2 to 1.16.5

1. `event.create('id', 'pickaxe')` does not exist → `event.create('id', b => { b.type('pickaxe') })` (`1605 .../item/ItemRegistryEventJS.java:21`, `.../ItemBuilder.java:116`).
2. `level.*`, `entity.hurt`, `client.generate_assets`, `item.model_properties` do not exist; use `world.*` and `entity.attack`.
3. `BlockStatePredicate` / `BlockProperties` globals are missing (`1802 :321`, `:351`).
4. `containsRecipe(...)` and `RecipeJS.modifyResult(...)` are 1.18.2-only (§3.5).
5. `command.registry` never fires (`1605 .../server/KubeJSServerEventHandler.java:77` commented out).
6. `// ignore: true` is ignored; only `// ignored: true`.
7. `appliedenergistics2:grinder` handler exists only in 1.16.5 (`1605 .../BuiltinKubeJSPlugin.java:446-448`).
8. Type wrappers accept `ItemType`/`BlockType`/`ToolType` but not `Tier`/`ArmorMaterial` (`1605 :401-402` vs `1802 :422-423`), so `.tier('iron')` is a name lookup in 1.16.5.

## 8. Gotchas — failures that look like "nothing happened"

1. **Wrong script type.** `onEvent('init'|'postinit'|'item.registry'|'block.registry'|'fluid.registry'|'worldgen.add'|'item.registry.tool_tiers', ...)` in `server_scripts` registers and never runs (`1802 .../event/EventJS.java:26-35`). The reverse works: `startup_scripts` receives server/client events first.
2. **Handler exceptions are swallowed.** A typo inside a `recipes` handler logs `Error occurred while handling event 'recipes': ...` and aborts only that handler (`1802 .../event/EventsJS.java:63-67`), so all recipes in it vanish — always read `logs/kubejs/server.txt`.
3. **Id casing.** Lowercase snake_case with dots: `item.registry`, `recipes.type_registry`, `item.registry.tool_tiers`. `onEvent` does no normalisation.
4. **`event.recipes.X` namespacing.** Valid: `event.recipes.minecraft.crafting_shaped(...)`, `event.recipes.minecraft.craftingShaped(...)`, `event.recipes.minecraft_crafting_shaped(...)`, `event.recipes.shaped(...)`. Invalid: `event.recipes.crafting_shaped(...)` → `"Unknown recipe type: crafting_shaped"` (`1802 .../recipe/RecipeEventJS.java:549`).
5. **`event.recipes.shaped` is `kubejs:shaped`** unless `serverOnly` is enabled (`1802 .../recipe/RecipeEventJS.java:118`) — such recipes are invisible to mods reading vanilla `minecraft:crafting_shaped` JSON.
6. **JSON vs text components.** `Text.of(...)` accepts a string, a `Component` or a JSON object (`1802 .../bindings/ComponentWrapper.java:30`); a JS object without `text`/`translate` renders empty. Use `{ text: 'x', color: 'gold' }`, not `'{"text":"x"}'`.
7. **Block tags: `tag()` vs `tagBoth()`.** 1.16.5 `tag(String)` tags the block only, `tagBlockAndItem(String)` tags both (`1605 .../block/BlockBuilder.java:332`, `:337`); 1.18.2 splits into `tagBlock`/`tagItem`/`tagBoth` (`1802 :536`, `:541`, `:530`).
8. **File order is not alphabetical.** Equal `priority` ⇒ filesystem order (`1802 .../script/ScriptFile.java:43-46`); two files creating the same item then fail in non-deterministic order.
9. **Only leading comments are directives** (`1802 .../script/ScriptFileInfo.java:49-61`); a `// priority:` after code is just a comment.
10. **`removeAll` is not a recipe method.** It exists on `LootEventJS` (:46) and `TagEventJS` (:187/:227); calling it on a recipe event throws.
11. **`block.drops` is not loot.** Loot is `block.loot_tables` (`1802 .../core/LootTablesKJS.java:31`); `block.drops` (1.16.5 only) is a cancellable runtime event (`1605 .../block/KubeJSBlockEventHandler.java:117`).
12. **`item.tooltip` and `item.model_properties` are client events** (`1802 .../client/KubeJSClientEventHandler.java:129`) despite their neutral names.
13. **Duplicate ids.** 1.18.2 throws `IllegalArgumentException("Duplicate key '...' in registry '...'!")` (`1802 .../RegistryObjectBuilderTypes.java:154`); 1.16.5 silently overwrites.
14. **`// packmode:` silently disables files** when it differs from `CommonProperties.get().packMode` (`1802 .../script/ScriptManager.java:78-81`).
15. **Datapack scripts are server scripts** (`1802 .../server/ServerScriptManager.java:67-75`); `item.registry` handlers placed there never run.
16. **`DataPackEventJS` cannot delete** — only `add`/`addJson` (`1802 .../script/data/DataPackEventJS.java:23-33`); override the id instead.
